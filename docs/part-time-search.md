# 알바 통합검색

알바 탭은 POST /api/part-time-search/collect를 사용합니다. 이 엔드포인트는 첫 원본 페이지에서 두 사이트의 합산 건수를 확인한 뒤 1000건 이하일 때만 나머지 전체 페이지를 수집합니다. 1001건 이상이면 추가 페이지를 요청하지 않고 범위 축소를 안내합니다. 내부 페이지 조회 및 호환용 POST /api/part-time-search/pages도 1000건 초과 요청은 거절합니다. criteria.keyword(최대20자), criteria.regionIds(시도 또는 시군구1개 또는 전국), 선택적인 criteria.neighborhoodId(알바몬 읍면동 코드), albamonPage/albaheavenPage(1부터 시작, null은 건너뛰기)를 받습니다. 검색어 또는 지역 중 하나는 필수입니다. 지역을 선택하면 검색어는 빈 문자열·공백·생략 모두 허용하며, 둘 다 없는 검색은 화면과 서버에서 차단합니다. 채용 검색은 계속 검색어가 필수입니다. 사이트별 성공/실패와 nextPage를 따로 유지하며 실패 시 같은 페이지를 재시도합니다. 고유번호로 중복을 제거하고 급여는 원문 단위로 표시합니다. 원문 클릭은 기존 브라우저 읽음 기록을 사용합니다.

방문/검색/공고 클릭은 기존 usage_events의 part_time 분류로 기록됩니다. 관리자 화면의 알바 집계와 검색기록에 포함됩니다. 검색 요청의 searchId/visitorId/sessionId를 방문 이벤트와 공유하며, 서버가 받은 응답을 search_events의 part_time 분류로 저장합니다. 초기 요청(양쪽 페이지 1)은 search, 추가 조회는 load_more로 구분합니다. 관리자 결과 건수·상태는 해당 검색 ID의 초기 응답 기준이며 누적 전체 건수가 아닙니다. 잡코리아/사람인 전용 컬럼에는 알바 개수를 넣지 않습니다. 검색 ID가 없는 구버전 요청은 연결할 수 없는 결과 행을 생성하지 않습니다. 이전에 저장되지 않은 결과 건수는 복원하지 않습니다.

시군구는 기존 지역 목록으로 지원합니다. 읍면동 선택 UI는 `frontend/src/neighborhoods.json`에 포함된 알바몬 원본 코드 목록을 즉시 표시하며, 선택할 때 검색 서버나 외부 API를 요청하지 않습니다. 검색 서버의 초기 기동이나 외부 API 지연이 동네 선택을 막지 않습니다. 목록은 `python frontend/scripts/update-neighborhoods.py`로 갱신하고 검토·배포합니다. 스크립트는 현재 시군구 전체의 공개 코드 API(`/codes/areas/korean/dongs/gucode?code=I010`) 응답을 검증하며 일부 요청이 실패하면 기존 파일을 교체하지 않습니다. 원본이 빈 목록을 반환한 지역은 읍면동 선택이 비활성화됩니다. 시도·시군구를 바꾸면 읍면동 선택을 초기화합니다.

서버의 GET /api/part-time-search/neighborhoods?regionId=I000_I010 과 검색 시 읍면동 검증은 `backend/src/main/resources/part-time/neighborhoods.json`의 동일한 원본 코드 목록을 사용합니다. 외부 코드 API를 검색 중에 호출하지 않습니다. 갱신 스크립트는 프런트엔드·백엔드 파일을 함께 갱신하므로 둘 다 배포해야 합니다. 서버는 시작 시 코드 형식·시군구 소속·중복을 검증하고, 검색에서도 선택된 시군구에 실제로 속한 읍면동인지 확인합니다. 잘못된 조건을 넓은 지역으로 대체하지 않습니다.

알바몬에는 읍면동 고유 코드를 `areas`로 전달합니다. 검색어가 비어 있으면 `/total-search` 대신 실제 지역 검색 페이지 `/jobs/area`를 사용하고, 해당 페이지의 `__NEXT_DATA__` 중 일반 공고와 페이지 정보를 읽습니다. 2026-11-07 공개 페이지에서 강남구·개포동 지역 조건과 검색어 없는 결과를 확인했습니다. 원본 제목·업체·근무지역·급여·등록일·마감일을 유지합니다.

알바천국은 읍면동을 선택하거나 검색어 없이 지역만 조회할 때 실제 `/job/area/mainlocal` 검색을 사용합니다. 2026-11-07 사용자가 직접 검색해서 제공한 **경기 구리시 인창동** URL에서 다음 요청 필드를 확인했습니다.

- `schnm=LOCAL`, `viewtype=L`, `sidocd=031`
- `strAreaMulti=031||구리시||인창동`, `selGugun=구리시`, `selDong=인창동`
- `hidListView=LIST`, `hidSortCnt=50`, `hidSortFilter=Y`, `hidSearchyn=Y`, `page=1`
- 검색어 없는 원본 요청에는 `schIncludeText`도 빈 값입니다. 검색어를 넣으면 별도의 `schIncludeText` 조건으로 보내며, 지역 이름을 검색어에 섞지 않습니다.

**표시 주소를 검사해 공고를 제외하는 로직은 제거했습니다.** 원본 검색이 반환한 공고는 표시 주소가 시군구까지만 있거나 비어 있어도 유지합니다. 응답의 `input[name=strAreaMulti]`가 요청 지역과 일치하는지 검사하고, 다르거나 확인할 수 없으면 FAILED로 처리합니다. 지역이 넓어진 응답을 정상 결과로 표시하지 않습니다. 일반 채용정보의 테이블(`#NormalInfo`)과 목록(`#jobNormal`)을 읽고 원본 전체 건수를 유지하며, 해당 원본 요청의 페이지 크기 50으로 다음 페이지를 계산합니다. 검색어만 있고 읍면동 조건이 없는 기존 통합검색은 기존 페이지 크기 20을 유지합니다.

실제 응답 검증: 사용자가 저장해 제공한 2026-11-07 구리시 인창동 HTML을 현재 파서에 직접 입력했습니다. 원본의 `strAreaMulti=031||구리시||인창동`, `hidSortCnt=50`, `page=1`, `getWnSearchPaging('1', '56', 50, 10, ...)`을 확인했습니다. 일반 채용정보 50행의 공고 ID를 원본 HTML에서 독립적으로 추출한 목록과 대조했으며, 파서의 50개 ID·순서가 모두 일치하고 누락은 0개였습니다. 반환 전체 건수는 56, 다음 페이지는 2이며 업체명·제목·급여도 50개 모두 비어 있지 않았습니다. `alba-inchang.html` 회귀 데이터에는 공고 파싱에 필요한 공개 목록 필드만 남겼으며 원본 전체 HTML·스크립트·이벤트 핸들러·계정 관련 내용은 저장소에 넣지 않았습니다. `alba-inchang-ids.txt`는 원본에서 별도로 추출한 50개 ID입니다. 표시 주소를 시군구까지만 남긴 변형에서도 50개를 모두 유지하는지 테스트합니다.

남은 검증 범위: 이 클라우드의 원본 직접 요청은 여전히 503·연결 시간 초과로 실패합니다. 따라서 이번 확인은 **사용자가 제공한 실제 1페이지 HTML과의 대조**이며, 배포 환경에서 실시간 요청 성공이나 실제 2페이지의 나머지 6개 공고 수신을 확인한 것은 아닙니다.

근무기간/요일/급여 조건은 아직 지원하지 않으며 필터에 표시하지 않습니다. 검색종류를 바꾸면 입력 및 현재 결과가 초기화됩니다. 읽음 기록은 유지됩니다. 서버의 페이지당 결과 개수와 유료 노출은 원본 사이트에 따라 다를 수 있습니다. 사이트 구조 변경이나 제한은 FAILED로 표시하고 0건으로 감추지 않습니다. 지역만 검색해도 방문 통계의 search_click을 기록하며, 읍면동 코드와 선택 당시 이름은 기존 search_criteria JSON의 neighborhood_id/neighborhood_name에 보관합니다. 관리자 화면은 이름이 없고 코드만 있는 과거 기록에 한해 해당 지역 코드 목록으로 이름을 확인합니다. DB 스키마 변경은 없습니다.

검증: PartTimeSearchServiceTest는 기존 파서/입력검증을 확인하고 Render 빌드에서는 실제 서버 통합조회도 실행합니다. PartTimeNeighborhoodsTest와 PartTimeNeighborhoodHttpTest는 고정 원본 응답으로 빈 검색어 허용, 둘 다 없는 검색 거절, 읍면동 소속 검증, 목록 캐시·재시도, 사용자가 제공한 원본 검색 조건, 주소가 생략된 공고 유지, 지역 조건 불일치 차단, 페이지 크기 및 HTTP 요청/응답을 검증합니다. 프런트 입력 검증 테스트와 데스크톱·모바일 브라우저 검증은 원본 사이트 응답을 대체하므로 실제 양쪽 사이트의 전체 동작을 보장하지 않습니다.

## 전체 수집·최신순 정렬

`/collect`는 `application/x-ndjson` 스트림으로 checking → collecting(현재/전체 건수) → sorting → complete 이벤트를 전송합니다. `error` 또는 `rejected`이면 완성된 검색 결과를 반환하지 않습니다. 일부 사이트 실패·중복 페이지 정체·총수와 실제 고유 공고 수 불일치·수집 중 1000건 초과는 전체 완료로 표시하지 않습니다. 수집은 최대 180초(진행 중 원본 요청의 최대 35초는 추가될 수 있음), 동시 전체 수집은 3개로 제한하고 브라우저 취소 시 다음 페이지 요청을 중지합니다. 내부 페이지마다 통계를 기록하지 않고 최종 수집 결과를 한 번 기록합니다.

수집 완료 후 두 사이트를 번갈아 섞는 대신 등록 표시 시점으로 전체 정렬합니다. 분·시간 전은 검색 시작 시각 기준 추정, 월/일은 한국 시간 기준 연도를 보완하며 날짜만 있으면 해당 날짜까지만 비교합니다. 같은 시점은 출처·공고 ID로 일정하게 배치하고 알 수 없는 날짜는 뒤에 둡니다. 원본 등록 시각의 정밀도를 넘어선 정확성이나 재등록 여부를 보장하지 않습니다. 알바몬 요청은 확인된 `sortType=POSTED_DATE`를 사용합니다. 알바천국 원본 정렬 파라미터는 확인되지 않아 기존 요청을 유지하며, 전체 수집 후 정렬하므로 원본의 페이지 순서에 의존하지 않습니다.

완료 화면에는 전체 검색 결과 건수와 25개 단위 페이지를 표시합니다. 사이트별 수집 비율·추가 불러오기 버튼은 알바 화면에서 제거했습니다. 페이지 이동 시 추가 수집이나 재정렬을 하지 않습니다. 채용 검색의 기존 페이지 방식은 유지합니다.

## 지역 다중 선택

알바 검색은 체크형 지역 선택창에서 최대 5곳을 선택합니다. 알바천국 원본 화면의 다중 선택 제한에 맞췄습니다. `criteria.locations`의 각 항목은 `regionId`, 선택적인 `neighborhoodId`, `neighborhoodName`을 함께 전달하며 기존 단일 지역·동네 요청도 호환됩니다. 전체 지역과 하위 동네는 동시에 선택하지 않도록 화면에서 정리합니다.

**각 원본 사이트에는 선택한 모든 지역을 한 검색 조건으로 전달합니다.** 알바몬은 `areas=B0700130,B0700100`, 알바천국은 사용자가 제공한 공식 다중 선택 URL대로 `strAreaMulti=031||구리시||인창동,031||구리시||수택동`과 반복되는 `selDong` 값을 전달합니다. 서로 다른 시도의 항목도 각 지역에 해당하는 원본 시도 코드와 명칭을 유지합니다.

지역별 요청·지역별 전체 건수 합산·지역별 결과 합치기 루프는 없습니다. 한 페이지 조회 시 알바몬 1회, 알바천국 1회이며 이후에도 각 사이트의 다음 페이지만 조회합니다. 1,000건 제한과 진행률은 각 원본이 계산한 다중 지역 검색의 전체 건수로 판단합니다. 전부 수집한 뒤 기존 최신순 정렬·25개 페이징을 적용합니다. 페이지 간 같은 공고 ID 중복 검사는 수집 정합성 확인용으로 유지합니다.

알바몬 실제 응답의 queryKey 조건에 모든 지역 코드가 적용됐는지 검증하고, 알바천국도 응답의 `strAreaMulti`가 요청한 지역 집합과 일치하는지 확인합니다. 조건이 누락되면 더 넓은 지역의 결과로 대체하지 않고 실패로 처리합니다. 알바몬의 검색어+다중지역 응답도 동일한 원본 JSON 구조를 확인했습니다.

관리자 검색 기록의 기존 `search_criteria.locations` JSON에는 각 지역과 읍면동 이름을 함께 보관합니다. DB 스키마 변경은 없습니다.
