## What is recorded

One event per completed, validated search/page request: random search ID, event ID,
redacted keyword, region IDs, career range, education, employment type, requested
pages, returned counts, outcome and server processing time.
Emails and common phone-number patterns are redacted from keywords. Other personal
information cannot be reliably identified by these patterns; the form asks users
not to enter personal information.
No IP, account ID, browser ID, user-agent or persistent visitor identifier is stored.

The frontend creates a new search ID for each submitted search and reuses it for
additional pages/retries. Count distinct search IDs for initial searches.
This does not measure unique visitors. Server time excludes cold-start and browser
network wait. Direct legacy API callers without a search ID get a fresh ID.

## Reliability and limits

The recorder uses one asynchronous worker, a 128-event memory queue, a 2-second
connection timeout and a 3-second HTTP request timeout.
Search responses do not wait for database writes. Database failures, queue overflow
and application shutdown can lose events. There is no durable retry queue.
Logs include operational failures only, not query text, request bodies or keys.
A pause/outage does not get replayed later.

The Free database has storage/inactivity limits. Monitor its size before increasing
traffic. No automatic deletion/retention job has been enabled; choose a retention
period before long-term operation. Queries below exclude the schema verification
row, which was verified inside a transaction and rolled back.

## Reports

Run these in the private SQL editor. There is no public statistics endpoint.

Daily searches in Korea time:
```sql
select (recorded_at at time zone 'Asia/Seoul')::date as day,
       count(distinct search_id) as searches
from public.search_events
where event_type = 'search'
  and recorded_at >= now() - interval '30 days'
group by 1 order by 1 desc;
```

Top search conditions:
```sql
select keyword, region_ids, career_type, minimum_career_years,
       maximum_career_years, minimum_education, employment_types,
       count(distinct search_id) as searches
from public.search_events
where event_type = 'search'
  and recorded_at >= now() - interval '30 days'
group by 1,2,3,4,5,6,7 order by searches desc limit 50;
```

Request reliability and server processing time:
```sql
select event_type, outcome, count(*) as requests,
       round(avg(duration_ms)) as average_server_ms
from public.search_events
where recorded_at >= now() - interval '7 days'
group by 1,2 order by 1,2;
```
